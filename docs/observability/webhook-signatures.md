# Webhook Signature Verification

AcmeX signs outbound webhook deliveries when `signing_secret` is configured on
the webhook target.

Required headers:

- `X-AcmeX-Event-Id`: stable event id. Consumers must store recently processed
  ids and reject duplicates according to their retention policy.
- `X-AcmeX-Signature-Timestamp`: UTC RFC 3339 timestamp generated by AcmeX.
- `X-AcmeX-Signature`: `sha256=<hex hmac>`.

Signature input:

```text
<X-AcmeX-Signature-Timestamp>.<raw request body bytes>
```

Verification order:

1. Require all three headers.
2. Parse `X-AcmeX-Signature-Timestamp` as an instant and reject values outside
   the configured replay window. The default `replay_window_secs` is `300`.
3. Recompute HMAC-SHA256 over the exact raw request body bytes and compare in
   constant time.
4. Deduplicate accepted `X-AcmeX-Event-Id` values before applying side effects.

Example configuration:

```toml
[[notifications.webhooks]]
url = "https://hooks.example.test/acmex"
signing_secret = "env:ACMEX_WEBHOOK_SIGNING_SECRET"
replay_window_secs = 300
```

Rust consumers can use `acmex::verify_webhook_signature(headers, body, secret,
Duration::from_secs(replay_window_secs))` and then apply their own event-id
deduplication store.
